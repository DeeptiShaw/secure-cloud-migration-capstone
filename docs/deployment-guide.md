# Deployment guide
## Foundation
Use an authorized AWS sandbox account, MFA and budget alerts. Install Terraform and authenticate using a short-lived AWS role. In infrastructure run `terraform init`, `terraform fmt`, `terraform validate`, `terraform plan -out=planfile`. Review cost and resources before `terraform apply planfile`. This template creates eight subnets, NAT per AZ, routing, security groups and RDS only; it has not been applied or provider-validated here.
## Remaining manual implementation
1. Create separate web/API EC2 launch templates (encrypted EBS, IMDSv2, no public IP, SSM access). Create ASGs with min/desired 2, max 4 across respective private subnets. Install Nginx and Python application runtime using approved images.
2. Initialize schema via an authorized temporary private migration host. Create a dedicated non-admin DB role with SELECT on products/orders, INSERT on orders and sequence usage. Store its credentials in Secrets Manager. Adapt the demo API to fetch the secret at runtime with boto3, use RDS CA trust and verify-full. Replace shared demo token with individual identity and per-user authorization before public access.
3. Configure TLS on web port 443 and API port 8443 (the local Docker config is HTTP only). Configure public ALB HTTPS 443 with ACM and HTTP redirect; internal ALB HTTPS 443 with private DNS and trusted certificate. Configure HTTPS target groups and /health checks. Configure Nginx reverse proxy to internal ALB; validate upstream TLS. ALB does not validate target certificates; evaluate additional authenticated transport if required.
4. Attach WAF common and SQLi managed rules and rate limit to public ALB. Create Route 53 alias. Enable S3 block public access, encryption, CloudTrail, Flow Logs, GuardDuty and CloudWatch alarms. Configure log retention and alerts; test secret rotation and patching.
5. Export source PostgreSQL with pg_dump, restore using pg_restore, reconcile counts and totals, freeze writes and synchronize final changes. Switch DNS only after approval. If rollback needed, stop writes and reconcile cloud changes before reverting DNS.
## Cleanup
Delete manual resources first, including ALBs and ASGs. Retain required backups. For authorized cleanup change RDS deletion protection to false and apply, then review `terraform plan -destroy` before `terraform destroy`. Check retained snapshots, logs, IPs and DNS for ongoing costs. Never delete production data without approval.
